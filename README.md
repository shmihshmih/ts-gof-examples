# 23 паттерна GoF на TypeScript

[Открыть шпаргалку](index.html). Файл открывается в браузере напрямую. На странице есть поиск по русским и английским названиям, короткие разборы и вопросы с раскрывающимися ответами.

Каждый пример — отдельный файл с комментарием, реализацией и сценарием запуска в конце.

## Как запустить

Понадобятся Node.js 20 или новее и npm.

```sh
npm ci
npm run check
npm run build
node dist/creational/factory-method.js
```

Для другого примера возьмите путь из таблицы, замените `src/` на `dist/`, а `.ts` на `.js`.

## Как повторять

Прочитайте задачу и попробуйте назвать паттерн по памяти. Начните с последних строк примера. Посмотрите, какой объект создаёт вызывающий код и кому он передаёт работу. Перед запуском предскажите вывод, затем ответьте на вопрос в браузерной шпаргалке.

- [Порождающие](#порождающие) помогают создавать объекты.
- [Структурные](#структурные) помогают связывать объекты.
- [Поведенческие](#поведенческие) распределяют действия и ответственность.

## Порождающие

| Паттерн | Когда пригодится | Как работает пример |
| --- | --- | --- |
| [Factory Method](src/creational/factory-method.ts)<br>Фабричный метод | Подкласс выбирает, какой объект создать для общей операции. | `Exporter.export()` вызывает `createFormatter()`. `CsvExporter` возвращает форматтер CSV, `JsonExporter` возвращает форматтер JSON. |
| [Abstract Factory](src/creational/abstract-factory.ts)<br>Абстрактная фабрика | Одна фабрика создаёт семейство совместимых объектов. | `renderForm()` берёт кнопку и поле ввода из одной `ThemeFactory`. Замена фабрики меняет тему обоих элементов. |
| [Builder](src/creational/builder.ts)<br>Строитель | Объект собирается по шагам. Строитель определяет форму результата. | `buildWeeklyReport()` передаёт заголовок и строки строителю. Два строителя выдают текст и структурированные данные. |
| [Prototype](src/creational/prototype.ts)<br>Прототип | Новый объект создаётся копированием готового экземпляра. | `ReportTemplate.clone()` копирует заголовок и массив разделов. Черновик можно редактировать независимо. |
| [Singleton](src/creational/singleton.ts)<br>Одиночка | Класс контролирует создание единственного общего экземпляра. | `EventLog.getInstance()` при первом вызове создаёт журнал. Дальнейшие вызовы возвращают тот же объект. |

## Структурные

| Паттерн | Когда пригодится | Как работает пример |
| --- | --- | --- |
| [Adapter](src/structural/adapter.ts)<br>Адаптер | Обёртка переводит вызовы между несовместимыми интерфейсами. | `PaymentAdapter.pay()` переводит рубли в копейки и вызывает `LegacyGateway.chargeKopecks()`. |
| [Bridge](src/structural/bridge.ts)<br>Мост | Две стороны системы можно расширять независимо друг от друга. | `Notification` хранит `DeliveryChannel`. Срочное уведомление и напоминание можно связать с любым каналом. |
| [Composite](src/structural/composite.ts)<br>Компоновщик | К отдельному объекту и группе объектов можно обращаться одинаково. | `Product.total()` возвращает цену. `Box.total()` вызывает этот же метод у всех вложенных элементов. |
| [Decorator](src/structural/decorator.ts)<br>Декоратор | Обёртки добавляют возможности отдельному объекту и могут сочетаться. | `WithMilk` и `WithCinnamon` реализуют `Drink`, делегируют вызов напитку и добавляют свой вкус и цену. |
| [Facade](src/structural/facade.ts)<br>Фасад | Один простой метод скрывает координацию нескольких частей системы. | `CheckoutFacade.placeOrder()` резервирует товар, проводит оплату и формирует чек. |
| [Flyweight](src/structural/flyweight.ts)<br>Приспособленец | Множество объектов совместно используют одинаковые данные. | `TreeKindFactory` переиспользует имя вида и текстуру дерева. Каждое `Tree` хранит собственные координаты. |
| [Proxy](src/structural/proxy.ts)<br>Заместитель | Заместитель решает, когда и как обратиться к настоящему объекту. | `LazyImage` реализует `Image` и создаёт `LoadedImage` при первом вызове `display()`. |

## Поведенческие

| Паттерн | Когда пригодится | Как работает пример |
| --- | --- | --- |
| [Chain of Responsibility](src/behavioral/chain-of-responsibility.ts)<br>Цепочка обязанностей | Запрос передаётся от обработчика к обработчику, пока кто-нибудь его не примет. | `ShippingHandler` берёт заявки о доставке и передаёт остальные дальше. `BillingHandler` берёт заявки об оплате. |
| [Command](src/behavioral/command.ts)<br>Команда | Действие и его параметры хранятся в объекте, который можно передать на выполнение. | `AppendText` хранит документ и добавляемую строку. `CommandHistory` запускает команду и сохраняет операцию отмены. |
| [Interpreter](src/behavioral/interpreter.ts)<br>Интерпретатор | Узлы простого языка умеют вычислять себя по правилам грамматики. | `Literal`, `Variable` и `Sum` образуют дерево выражения. `Sum.interpret()` вычисляет оба дочерних узла. |
| [Iterator](src/behavioral/iterator.ts)<br>Итератор | Коллекцию можно обходить последовательно, не зная, как она хранит элементы. | Генератор в `Playlist[Symbol.iterator]()` отдаёт треки из нескольких групп одной последовательностью. |
| [Mediator](src/behavioral/mediator.ts)<br>Посредник | Объект-посредник задаёт правила взаимодействия участников. | `Member.send()` передаёт сообщение в `ChatRoom`. Комната находит адресата и вызывает у него `receive()`. |
| [Memento](src/behavioral/memento.ts)<br>Снимок | Объект сохраняет своё состояние для последующего восстановления. | `Editor` создаёт и восстанавливает снимки. `EditorHistory` хранит их между правками. |
| [Observer](src/behavioral/observer.ts)<br>Наблюдатель | Источник сообщает о событии всем текущим подписчикам. | `Thermometer.report()` вызывает функции экрана и вентиляции. Каждая подписка возвращает функцию отписки. |
| [State](src/behavioral/state.ts)<br>Состояние | Текущее состояние определяет поведение объекта и его переходы. | `Publication.advance()` передаёт управление текущему `PublicationState`, который возвращает следующий этап. |
| [Strategy](src/behavioral/strategy.ts)<br>Стратегия | Вызывающий код выбирает взаимозаменяемый алгоритм. | `Basket.total()` получает `pickup` или `courier` и делегирует функции расчёт стоимости доставки. |
| [Template Method](src/behavioral/template-method.ts)<br>Шаблонный метод | Базовый класс сохраняет порядок алгоритма, подклассы определяют отдельные шаги. | `SalesReport.generate()` считает итог и собирает отчёт. Подклассы форматируют заголовок и строки. |
| [Visitor](src/behavioral/visitor.ts)<br>Посетитель | К набору типов можно добавлять целые операции через новых посетителей. | `Circle.accept()` вызывает `visitCircle()`, а `Rectangle.accept()` — `visitRectangle()`. У каждого посетителя своя операция. |

## Как различать похожие паттерны

- **Factory Method и Abstract Factory.** Factory Method отдаёт выбор отдельного продукта подклассу. Abstract Factory выдаёт набор совместимых продуктов через один интерфейс.
- **Builder и Template Method.** Builder отделяет общие шаги создания от представления результата. Template Method фиксирует порядок алгоритма в базовом классе и позволяет подклассам переопределять его шаги.
- **Adapter, Decorator и Proxy.** Adapter переводит между интерфейсами. Decorator добавляет поведение и сохраняет интерфейс. Proxy сохраняет интерфейс и управляет доступом к объекту.
- **State и Strategy.** State связывает поведение с текущим этапом и его переходами. Strategy отдаёт выбор алгоритма клиенту.
- **Observer и Mediator.** Observer рассылает событие подписчикам. Mediator ведёт взаимодействие участников по правилам.
- **Command и Memento.** Command представляет действие. Memento хранит состояние. В истории действий команда может использовать снимок для отмены.
